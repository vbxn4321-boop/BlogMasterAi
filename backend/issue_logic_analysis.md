# "이슈성" (Issue/Trendiness) 분석 결과

현재 시스템에서 "이슈성" 지표가 어떻게 구현되어 있고 시각화되는지에 대한 분석 결과입니다.

## 1. 프론트엔드 시각화 방식 (`page.js`)
- **컴포넌트**: `PieChart` (Recharts 라이브러리)를 사용하여 원형 그래프로 그려집니다.
- **데이터 바인딩**: `result.seed_analysis.issue_score` 값을 사용합니다.
- **기본값(Mock)**: 백엔드에서 해당 값이 내려오지 않을 경우, 코드상에서 **`0.5%`를 기본값**으로 설정하여 보여주고 있습니다.
  ```javascript
  { name: '이슈', value: result.seed_analysis.issue_score || 0.5 }
  ```

## 2. 데이터 소스 및 계산 로직 분석
- **백엔드 현황**: `keyword_analysis.js` 및 `engine_api.js` 등 전체 백엔드 코드를 분석한 결과, `issue_score` 또는 "이상치(Outlier) 비율"을 계산하는 로직은 **현재 존재하지 않습니다.**
- **설명 문구의 기원**: UI상에 나타나는 "2016-01-01 ~ 현재까지... 이상치 비율"이라는 설명은 프론트엔드 `page.js` 내 `descriptionMap`에 **하드코딩된 정적 텍스트**입니다.
- **데이터 공백**: 실제 백엔드 분석 엔진은 현재 최대 12개월치(`getDatalabTrend`) 또는 60일치(`getPreciseTrend`) 데이터만 조회하며, 2016년부터의 장기 데이터를 분석하는 로직은 미구현 상태입니다.

## 3. 결론 요약
현재 화면에 그려지는 이슈성 그래프는 **프론트엔드에 설정된 설명과 기본값(0.5%)을 바탕으로 출력되는 단계**이며, 실제 2016년부터의 데이터를 분석한 결과값은 아닙니다. 

이 기능을 실제로 작동하게 하려면 네이버 데이터랩 API를 통해 2016년부터의 전체 일별 데이터를 받아와 표준 편차 등을 활용한 이상치 검출 로직을 백엔드에 추가해야 합니다.
